# Blue Blood Mark Implementation Plan

**Goal:** Ship Blue Blood as rung 2 of the Mark ladder, replacing the dropped
Pulse, by tinting the noise ink slate blue.

**Architecture:** The noise ink is already a parameter of `CodeRenderer.paths`,
so the Mark is a colour selection and nothing more -- the same shape as Vein,
Halo and Crown. `Palette` gains a second five-entry table; `MarkRenderer` picks
between the two by rung; `Renderer` routes the existing call through it. The JS
reference renderer mirrors every value, and the differential test holds the two
byte for byte.

**Tech Stack:** Solidity 0.8.35 (Foundry, via_ir), Node 24 with `node --test`.

## Global Constraints

- Plain ASCII only in all docs and code comments.
- Every colour constant MUST exist identically in `contracts/src/render/` and
  `tools/render-token.mjs`; `Renderer.t.sol` diffs the two renderers.
- The luminance match is not negotiable: `|luma601(heart) - luma601(noise)| <= 1`
  at every rung, for BOTH palettes.
- New rule: with Blue Blood worn, `chroma(noise) < chroma(heart)` at every rung.
- Generated files carry `// GENERATED by tools/<script>` and are never
  hand-edited.
- `forge build --sizes` must show positive runtime margin before done.
- Foundry needs `export PATH=$HOME/.foundry/bin:$PATH`; Node needs
  `source ~/.nvm/nvm.sh`.
