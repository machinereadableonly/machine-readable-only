**Goal:** The token contract carries every redeploy-only change ruled on
2026-09-30 (rulings 2 and 3), the Renderer and its JavaScript mirror draw them,
and the Warden and Clock speak the new interface -- all proven by tests, on a
branch, with nothing deployed.

**Why:** The token contract can never change after the mainnet mint of token
1. Ruling 3 put six additions into the one redeploy left, and ruling 2 kept
`seed`'s key check. Roadmap Plan A is too large for one plan, so it is split
along its seams, one plan each, all on one branch and deployed once:

| Plan | What | Deploys? |
|---|---|---|
| **A1 (this)** | Rulings 2 and 3, four small contract fixes, the Warden and Clock follow | No |
| A2 | The daily question on chain: answer bits, key chain, `setSplitAnchor`, the three answer edges, the Clock's split, `verify-border` | No |
| A3 | Size and gas gates over both, the Base Sepolia redeploy, `adopt-deployment.sh`, re-pointing the test agent | Yes, Sepolia |

**What approving this plan also approves** -- each is a choice, named here so
it is made out loud:

1. **Art: a rested token is drawn exactly as it was on its rest day, forever.**
   Today resting restores the token's full colour however long it had been
   away (a token silent two years goes back to its top colour the moment it
   rests). Storing the rest day exists to fix that, so the image is frozen at
   that day under the same rules a live token follows.
2. **Art: a sunset keeps the fallen-run colour.** The same one rule
   (`_stopDay`) serves rest, sunset and a finished year, so a sunset token that
   slipped and came back keeps its fallen-run colour instead of dropping to the
   lower one. Renderer-only; flagged by the same review finding.
3. **Four one-line contract fixes the review proved REAL** and that only a
   redeploy can make: `rest` refuses a token already resting (it re-emitted a
   second rest day); `heartbeat` refuses after sunset; a finisher Mark record
   (ids 11-15) can be written once and never edited; `mint` and `seed` use
   `_mint`, not `_safeMint` (the Warden already refuses a recipient that cannot
   hold a token before payment, and the callback only let a recipient contract
   cost the Clock a failed transaction a night).
4. **contractURI carries name, symbol, description and link, and no image.**
   The token description is reused word for word. An image can be added by a
   renderer swap at any time until the renderer is frozen.

**Architecture:** All contract changes are in `MachineReadableOnly.sol`, plus
`IRenderer` gaining `contractURI()` and `TokenView` gaining `restDay`. The
Renderer gets one helper, `_stopDay`, used by both `_rung` and `_absence`, and
the `external_url` field; `tools/render-token.mjs` mirrors both byte for byte.
The Warden regenerates its ABI; the Clock sends the parent's key with `seed`
and lets the chain's `StaleDay` condemn only the stale day's entries.

**Tech Stack:** Solidity 0.8.30 / Foundry 1.7.1 (via_ir), Node 24.14.1,
`node:test`, viem.

**Spec:** `docs/reviews/2026-09-28/00-verification.md` (Contract section and

`19-mro-qver.md` and `38-mro-sver.md`; `docs/plans/2026-09-30-mro-rulings-roadmap.md`

## Review Focus

1. **The lateness boundary:** a check-in exactly 30 days behind `today()` is
   accepted; 31 is refused `StaleDay(day)` -- on BOTH the batch and the voucher
   path. Pinned in Task 1.
2. **A batch carrying one stale day among fresh ones:** the contract reverts
   the whole batch, and the Clock condemns only that day's entries and writes
   the rest. Pinned in Task 6.
3. **A parent rebound between the seed request and the Clock's write:** the
   chain refuses `KeyChanged(parentId)` before it spends any budget, and the
   Clock drops the row so the agent's year comes back. Pinned in Tasks 2 and 6.
4. **Rest and sunset in either order, and a finished token that rests later:**
   the earliest stop wins, and a finished token never pales by resting.
   Pinned in Task 5, in both languages.
5. **The freeze is one-way and owner-only:** a second freeze, a swap after it
   and a stranger's freeze are all refused; the constructor still sets the
   first renderer. Pinned in Task 3.

```solidity
    /// @dev Credit `n` consecutive days from `firstDay`, at most 30 per batch,
    /// because the contract refuses a credit more than MAX_LAG days late.
    /// Ends with the clock on the last credited day.
    function _creditRun(uint256 id, uint32 firstDay, uint32 n) internal {
        uint32 done = 0;
        while (done < n) {
            uint32 m = n - done > 30 ? 30 : n - done;
            uint32[] memory ids = new uint32[](m);
            uint32[] memory ds = new uint32[](m);
            for (uint32 i = 0; i < m; i++) {
                ids[i] = uint32(id);
                ds[i] = firstDay + done + i;
            }
            _warpToDay(firstDay + done + m - 1);
            vm.prank(WARDEN);
            t.batchCheckIn(_packed(ids), ds);
            done += m;
        }
    }
```

Replace the bodies of `_makeWhole` and `_growTo` (keep their doc comments; the
clock still ends 364 days on for `_makeWhole`, so the seed-budget arithmetic
holds):

/** The day the picture stops moving. MUST mirror Renderer._stopDay. */
export function stopDay({ lastDay, today, resting = false, restDay = 0, sunset = false, sunsetDay = 0, whole = false }) {
  if (whole) return lastDay;
  let at = today;
  if (sunset && sunsetDay < at) at = sunsetDay;
  if (resting && restDay < at) at = restDay;
  return at;
}

export function absenceOf(s) {
  const end = stopDay(s);
  return end > s.lastDay ? end - s.lastDay : 0;
}

export function rungFor(s) {
  const at = stopDay(s);
  const live = lapsedRung(s.streak, s.lastDay, at);
  if (!s.fellRun) return live;
  const cap = Math.max(0, rungOf(s.fellRun) - 1);
  const fell = Math.min(lapsedRung(s.fellRun, s.fellDay, at), cap);
  return Math.max(fell, live);
}
